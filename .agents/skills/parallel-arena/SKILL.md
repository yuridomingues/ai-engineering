# Parallel Arena

## When

Use when diversity of independent reasoning is likely to outperform one long chain.

Do not use for simple mechanical edits.

## Procedure

1. Define the same problem statement and constraints for all candidates.
2. Keep candidates independent; do not cross-pollinate before judging.
3. Ask each for:
   - proposed design
   - tradeoffs
   - risks
   - verification plan
4. Normalize outputs.
5. Judge using an explicit rubric.
6. Select or synthesize.
7. Implement the winner.
8. Verify in the real environment.

## Rubric dimensions

Common dimensions:
- correctness
- simplicity
- maintainability
- migration cost
- performance
- security
- testability
- reversibility

Weight them for the actual task.
