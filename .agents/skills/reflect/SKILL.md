# Reflect

Reflection is an infrastructure step, not a diary entry.

For each meaningful failure classify the missing leverage:

- missing knowledge -> improve map/docs
- missing tool/observable -> expose a reusable capability
- ambiguous contract -> improve schema/template
- repeated coding mistake -> test/lint/type/policy
- orchestration error -> change DAG/ownership/concurrency rule
- verification blind spot -> add feature map/runtime evidence path
- context pollution -> isolate/reset/handoff
- model weakness -> route differently or constrain the task

## Promotion order

Prefer the strongest reusable control:

1. type/schema
2. compiler/static analysis
3. deterministic test
4. lint/policy/architecture rule
5. workflow gate
6. tool/interface improvement
7. skill
8. free-form prompt reminder

Add a regression eval when the failure concerns probabilistic agent behavior.

Do not add a new rule if an existing rule can be made executable instead.
